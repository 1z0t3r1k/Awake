# Android: интеграция с текущим бэкендом

Изменения ограничены каталогом `android`. Контракт проверен по контроллерам, DTO, перечислениям и сервисам в текущем `src`, включая незакоммиченные изменения.

## Что исправлено

- Ответы без тела используют Retrofit `Unit`: ошибки HTTP теперь выбрасываются, а не воспринимаются как успешный результат. Неуспешная отправка событий не удаляет их из очереди.
- Ротация refresh-токена защищена от выхода и смены аккаунта во время запроса. Публичные запросы регистрации, входа, обновления и выхода не используют старый access-токен. Временная ошибка обновления токена сохраняет локальную сессию.
- Выход очищает локальную сессию и очередь даже при недоступном сервере. Вход, выход, удаление аккаунта и отправка телеметрии сериализованы, чтобы события одного аккаунта не отправлялись другому. Новый вход очищает старую очередь.
- Добавлено удаление аккаунта через `DELETE /api/v1/users/me`, с отдельным подтверждением в профиле. При ошибке удаления локальная сессия сохраняется.
- Данные Sleep API сохраняются до отправки; WorkManager повторяет отправку при подключении. События зарядки принимаются через системный receiver. События экрана принимаются во время жизни процесса приложения, включая свёрнутый интерфейс.
- Для нового аккаунта устанавливается часовой пояс устройства. Сбой последующей настройки профиля не превращает успешную регистрацию в ошибку регистрации.
- Поиск не показывает предыдущие результаты во время нового запроса; отменённые запросы не создают сообщения об ошибках.
- Расписание проверяет разные часы сна и пробуждения, показывает серверный часовой пояс и не создаёт стандартное расписание нажатием переключателя до первого сохранения.
- Диалог профиля остаётся открытым до подтверждённого сохранения. Удаление друга показывает процесс и не закрывает страницу до ответа. Ошибки загрузки друзей видимы пользователю.
- Сессия и телеметрия исключены из резервных копий и переноса данных устройства.

## Firebase

Клиент подготовлен для `PUT /api/v1/device-registrations` с JSON `{"firebaseInstallationId":"..."}`. Включён FID-режим FCM, используется `onRegistered`, а не устаревший FCM token. Регистрация повторяется через WorkManager, при выходе выполняется unregister. Уведомления обрабатываются в открытом приложении; разрешение на уведомления запрашивается через действие в профиле.

Чтобы включить Firebase, добавьте Android-приложение с package name `com.amiawake.android` в нужный Firebase-проект и поместите клиентский `google-services.json` в `android/app/`. Плагин Google Services подключается автоматически при наличии файла. Без файла остальные функции клиента работают, но push отключён.

Файл `am-i-awake-c642d-firebase-adminsdk-fbsvc-53b0f95b18.json` в предоставленном каталоге — серверный Admin SDK ключ. Он не скопирован в клиент и не использован для конфигурации Android.

Официальная инструкция FID: https://firebase.google.com/docs/cloud-messaging/android/get-started#access-the-firebase-installation-id

## Сборка и адрес API

Используйте JDK 17 или 21; установленный Android Studio JBR 25 несовместим с текущим Gradle 8.11.1.

```powershell
cd android
.\gradlew.bat :app:assembleDebug :app:lintDebug :app:testDebugUnitTest --max-workers=2
```

По умолчанию адрес API: `http://10.0.2.2:8080/` для Android-эмулятора. Для телефона задайте доступный адрес компьютера через `-PapiBaseUrl=http://<адрес-компьютера>:8080/`. Завершающий `/` обязателен. Для реального развёртывания используйте HTTPS.

## Проверки и ограничения

Проверки HTTP выполняются через MockWebServer: подтверждение ответов 204, отказ при 4xx/5xx, формат событий и регистрации устройства, поля профиля/друзей/сна, обновление токенов, временные ошибки обновления, выход и смена аккаунта во время запроса. Это проверка контрактов и сетевого поведения; живой сервер и доставка push не проверены.

В текущем бэкенде `WakeSubscriptionService` есть, но REST-контроллера подписки на пробуждение нет. Клиент не придумывает адреса API для этой функции. Также нет API снятия регистрации устройства; unregister выполняется через FCM.

События экрана не гарантируются после завершения процесса Android. WorkManager выполняется по правилам системы и не гарантирует точный интервал 15 минут. Sleep API зависит от Google Play Services и разрешения физической активности. Бэкенд не имеет ключа идемпотентности для классификаций сна: при потере ответа на успешно принятый запрос повторная отправка может создать дубликат. При новом входе старая локальная очередь очищается для изоляции аккаунтов.

Без клиентского Firebase-конфига нельзя проверить регистрацию FID и доставку уведомлений. После его добавления требуется проверка на устройстве с Google Play Services.
